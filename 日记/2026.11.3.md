## 🔥 核心难点、关键代码与攻坚复盘

### 1. 大画布减少渲染时仍要保住交互状态

**涉及文件**：`canvasVisibility.ts`、`useCanvasViewport.ts`、`WorkflowCanvas.tsx`。**难点所在**：简单按位置卸载卡片，会影响展开内容、拖动状态和长文本；用裁剪后的数组生成连线还会改变原始连接关系。

**关键代码**（`useCanvasViewport.ts` 真实节选）：

```ts
// 只有越过缓冲边界才同步补充少量节点，快速大幅拖动也不会先出现空白帧。
if (sync) flushSync(() => setRenderBounds(nextBounds));
else setRenderBounds(nextBounds);
```

**攻坚方案**：以缓冲视口减少 React 更新，保留正在交互的卡片，记录实际高度；连线先按完整任务顺序建立，再单独筛选可见部分。相关提交为 `df7f2fe`，未据此推断实际帧率提升幅度。

### 2. 点位切换后曲线仍停留在首屏数据

**涉及文件**：水位、流量组件及 `monitorChartConfig.ts`。**难点所在**：只刷新下拉选项不足以更新曲线，快速操作还可能使旧响应回填。

**关键代码**（`monitorChartConfig.ts` 真实节选）：

```ts
const list = await fetchTagKeys(currentInstallationId, tagType.value || undefined)
// 过期响应或 null（请求异常）时保留现有点位列表

```

**攻坚方案**：监听 tag 选项变化请求对应类别数据，以局部结果优先绘图；tag 查询及曲线查询分别使用请求序号。设施名称、类型查询及回到初始化数据时的并发边界仍需验证，不能视作全链路竞态已解决。
