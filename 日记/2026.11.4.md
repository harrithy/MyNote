## 🔥 核心难点、关键代码与攻坚复盘

### 1. 插件示例与实际 UTS / Kotlin 接口不一致

**涉及文件**：`appdemo/common/fcm-bridge.js`、`uni_modules/Jairo-FCM/utssdk`。**难点所在**：旧调用示例、选项交叉类型和原生数组、回调签名不能直接混用。

**关键代码**（`utssdk/app-android/index.uts` 真实节选）：

```ts
// Android API 接收原生 Array<String>，需将 UTS 数组显式转换。
ActivityCompat.requestPermissions(activity, ['android.permission.POST_NOTIFICATIONS'].toTypedArray(), 9931)
```

**攻坚方案**：按实际模块封装 `success/fail` 与超时保护，调整具名选项、Activity 获取、可空 Void 回调和消息数组类型。权限请求立即返回的是当前授权状态，弹窗操作后仍需再次核验。

### 2. HTTP 成功不能直接当作登记成功或推送送达

**涉及文件**：`appdemo/common/fcm-api.js`、后端 `internal/handler/push.go`。**难点所在**：Node 直接返回 JSON，Go 使用响应信封；代理可能让业务失败以 HTTP 200 返回。

**关键代码**（`fcm-api.js` 真实节选）：

```js
// Go 使用 { code, data, msg }；业务失败即使被代理为 HTTP 200 也不能报同步成功。
if (typeof body.code === 'number' && Object.prototype.hasOwnProperty.call(body, 'data')) {
  if (body.code < 200 || body.code >= 300) throw new Error(message || `后端返回错误 ${body.code}`)
  return body.data
}
```

**攻坚方案**：分别检查 HTTP、JSON 与业务码，展示 `msg/error`，避免网页地址或数据库错误被误报成功；发送接口的 `accepted` 仅表示 FCM 接受请求，手机接收需另行确认。
