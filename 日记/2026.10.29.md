## 🔥 核心难点、关键代码与攻坚复盘

### 1. 异步图层创建生命周期导致的图例显隐初始值竞争覆盖

- **涉及文件**：`D:\yin\gddst-coss-frontend\src\components\arcgis\index.vue`
- **难点所在**：地图底图与业务图层加载是异步流程，图例通常先于图层初始化完成。若用户在图层加载完毕前已变更勾选状态，当业务侧调用 `showFeatureLayer` 完成图层加入后，底层的原生流程还会继续给图层赋默认 `visible`，导致用户当前的图例选择被后置的原生逻辑覆盖失效。
- **关键代码片段**：

```typescript
/** 绑定显式关联图层的新增监听，并同步已有图层；未配置 layerId 的存量页面不启用 */
const bindLegendLayerVisibility = () => {
  legendLayerAddedHandle?.remove();
  legendLayerAddedHandle = null;
  const map = mapObj?.map;
  if (
    !map ||
    !legendControlEnabled.value ||
    !legendOpeList.value.some((item) => item.layerId)
  ) {
    return;
  }
  legendLayerAddedHandle = map.layers.on("after-add", () => {
    // showFeatureLayer 在 map.add 后还会设置初始 visible，待本轮创建结束后再按最新勾选同步
    queueMicrotask(() => {
      if (mapObj?.map === map && !map.destroyed) {
        applyLegendLayerVisibility();
      }
    });
  });
  applyLegendLayerVisibility();
};
```

- **攻坚方案**：在 `ArcgisMap` 中针对显式配置 `layerId` 的图层统一注册 `after-add` 监听器，并在微任务队列（`queueMicrotask`）中执行显隐校准。这样既确保了在宏任务中 `map.add` 及其后续所有的同步赋初值逻辑全部执行完毕，又避免了延迟闪烁，同时增加 `map.destroyed` 安全防御，避免实例切换时的内存泄漏与脏状态。

### 2. 跨路由多选参数按索引配对与结构化状态恢复

- **涉及文件**：`D:\yin\gddst-coss-frontend\src\router\index.ts`
- **难点所在**：多选模式下允许同时选中不同供水类型（食水、冲厕水）下的多个供水区。若将复合数据以复杂的 JSON 字符串编码进 URL，极易遇到 URI 长度截断或可读性差问题；若直接以扁平 query 传递，则需要在路由层面解决双数组并发传递时的容错、缺失兜底以及按索引恢复成业务分组对象的问题。
- **关键代码片段**：

```typescript
props: (route) => {
  const toList = (value: unknown): string[] =>
    Array.isArray(value)
      ? value.filter((item): item is string => typeof item === "string")
      : typeof value === "string"
        ? [value]
        : [];
  const supplyCodes = toList(route.query.supplyCode);
  const waterTypeCodes = toList(route.query.waterTypeCode);
  // 两个数组按索引一一对应：把同一供水类型的编码聚合为一个分组
  const groupMap = new Map<string, string[]>();
  supplyCodes.forEach((supplyCode, index) => {
    const waterTypeCode = waterTypeCodes[index] ?? "";
    const codes = groupMap.get(waterTypeCode) ?? [];
    codes.push(supplyCode);
    groupMap.set(waterTypeCode, codes);
  });
  return {
    zoneGroups: [...groupMap].map(([waterTypeCode, codes]) => ({
      waterTypeCode,
      supplyCodes: codes,
    })),
  };
};
```

- **攻坚方案**：使用 Vue Router 的动态 `props` 函数在路由切面层直接完成参数契约转换。先将 query 规范化为安全字符串数组，随后利用 `Map` 按照索引配对将同一类型的 `supplyCode` 归纳收拢为 `zoneGroups` 分组传递给目标组件，使得下游视图组件 `detail/index.vue` 保持纯粹的声明式输入。
