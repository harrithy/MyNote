## 🔥 核心难点、关键代码与攻坚复盘

### 1. 聚合数量与点击行为保持一致

- **涉及文件**：`recorderLayerConfig.ts`、`recorderClusterPopup.vue`、`trafficCameraLayer.ts`。
- **难点所在**：记录仪各状态既要共同聚合，又要遵循图例筛选；放大到上限后仍重叠的点需要逐项查看。
- **关键代码**：`buildRecorderLayerData` 先筛状态再聚合，`handleClusterClick` 按实际缩放上限决定放大或展示列表，事件携带 `layerId` 区分业务图层。
- **攻坚方案**：记录仪、现场图片、摄像头分别聚合；记录仪列表可进入单台监测卡片。摄像头按对象 ID 分批查询，遇服务传输上限继续拆分批次，避免拿截断结果计算数量；过期请求丢弃，临时服务图层统一释放。

### 2. 水印时间与上传文件一致

- **涉及文件**：`components/im/image-upload.vue`、`utils/im-photo-watermark.js`。
- **难点所在**：排队上传时间不等于定位时间，照片方向与合成后体积也会影响最终文件。
- **关键代码**（上传体积校验节选）：

```javascript
// 合成后重新校验实际体积；失败时停止本张上传，不能退回没有时间的图片。
const maxSize = Math.min(this.maxSize || imageMaxBytes, imageMaxBytes);
if (!(info.size > 0 && info.size < maxSize)) throw new Error('Watermarked image too large');
```

- **攻坚方案**：沿用照片保存的 `locatedAt`，先处理 EXIF 方向，再绘制时间并上传合成文件；失败终止本张，最终清理水印和压缩临时文件、释放位图。范围仅为 Android 群聊现场拍照，时间仍依赖手机时钟及本地时区。
